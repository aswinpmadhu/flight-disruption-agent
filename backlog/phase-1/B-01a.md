# [domain] Shared models and enums (B-01a)

**Phase: P1 · Wave 1 · Milestone cell: M2 · Priority P0 · Unassigned.**
**Blocked by:** none. **Blocks:** B-17a, B-01b, B-04, B-06, B-03, B-02, B-27. **Effort:** 1.0 h (planning estimate; the claimant replaces it). **Class:** CT.
**Prep:** none.
**Scope:** enums `DisruptionType` (CANCELLATION, MISSED_CONNECTION, DELAY, NONE) and flight status (ON_TIME, DELAYED, CANCELLED). Models: `Segment` (flight_number, origin, destination, scheduled_departure, scheduled_arrival); `Booking` (pnr, passenger_name, `cabin`, booking_status, `segments[]`); `FlightStatus` (status, scheduled and estimated times, `delay_minutes`; the `display` strings are produced by the B-16a handler, not stored); `Itinerary` (`itinerary_key`, `segments[]`, departure, arrival, `connections`, `seats_available`; **no `option_id`**); `PolicyPassage` (policy_id, section_id, section_title, `citation`, text, score); `PolicySearchResult` (`passages[]` at most 3, `no_relevant_policy`). Pydantic v2, frozen, `extra="forbid"`, timezone-aware UTC datetimes (T7). **`itinerary_key` (approved key contract, see the DK10 block below):** this issue owns a pure function `derive_itinerary_key(segments) -> str` implementing DK10 items 1 to 3 and a validator on `Itinerary` that rejects a key differing from the derived value. **Roles, exactly:** B-01a defines (a) the pure helper `derive_itinerary_key(segments) -> str` (no I/O, no clock, no randomness) and (b) the `Itinerary` validator. The validator uses the helper **only to verify a supplied key**: it derives the key from the segments, compares it as an exact string with the supplied `itinerary_key`, and raises on a difference; it never parses a key and never repairs or replaces a supplied key. **B-08a is the only production component that constructs a key** (by calling the helper from `flight_agent/services/alternatives.py`). **No other component constructs or parses a key**; all others treat it as an opaque string and compare exact strings. Tests, including this issue's own, may call the helper to build expected values. This issue also owns the static test `test_dk10_single_producer` (rules listed after the Tests line) that enforces these roles. The delay and missed-connection enum values are **dormant contract values**: no behaviour, no Phase 1 acceptance criterion.
**Files:** `flight_agent/domain/models.py`, `tests/unit/test_contract_models.py`, `tests/unit/test_dk10_single_producer.py`.
**Interface (fixed here):** this text. **It is frozen when published; a name that must change is edited into this text and the preparers of B-01b, B-17a, B-04, B-03, B-02 and B-06 are told before the PR is ready.**
**Acceptance criteria:** models immutable and reject unknown fields and naive datetimes; `flight_number` must match `^MD[0-9]{3}$`; the key follows DK10 and a mismatched key is rejected; the helper is pure; the validator never modifies a supplied key; **`test_dk10_single_producer` implements the producer, verifier and no-parse rules listed below and passes its self-tests (a call in `alternatives.py` passes; calls in a handler, `rebooking.py`, `manager.py` or `checks.py` fail; an aliased call elsewhere fails; an import without a call passes; a docstring or comment mention passes; a call from a non-validator function of `models.py` fails; a call from the `Itinerary` validator passes; `itinerary_key.split("+")` fails) and passes on the repository as merged**; no logic beyond validation and derivation; no `__init__.py` edits; after merging, comment on each dependent.
**Tests you own:** `test_contract_models_*` including the DK10 examples (`MD101:2026-12-01`; two segments one date; two segments across midnight `MD101:2026-12-01+MD205:2026-12-02`), key unchanged when an estimated time crosses midnight UTC, `md101`, `MD1011`, `MD10` rejected, mismatched key rejected; `test_dk10_single_producer`.
**Out of scope:** error codes, envelope, Protocols. **References:** FR-12 to FR-14, FR-16, T7; docs/03 §4, §5.4, §5.6.
**Rules of `test_dk10_single_producer`.** It applies three rules to every `*.py` file under `flight_agent/` (the `tests/` tree is excluded), parsed with `ast.parse` and tracking import aliases (`import m as x`, `from m import derive_itinerary_key as k`): (1) **Producer rule:** a *call* to `derive_itinerary_key` may appear only in `flight_agent/domain/models.py` and `flight_agent/services/alternatives.py`. (2) **Verifier rule:** inside `models.py` the helper may be called only from the validator method(s) of class `Itinerary`; the helper's own `def` is not a call. (3) **No-parse rule:** nothing under `flight_agent/` may split, partition, slice, index or regex-match a value named `itinerary_key` or `<expr>.itinerary_key` (`.split`, `.rsplit`, `.partition`, `.rpartition`, `.removeprefix`, `.removesuffix`, subscripts and `re.*` calls taking it as an argument fail). Imports, comments, docstrings, string constants, type annotations and non-call references never fail rules 1 and 2; a file that does not parse fails. **Stated limit:** dynamic indirection (`getattr`, `globals()`, `importlib`, assigning the function to another name, `functools.partial`) is not detected; code review covers it.
