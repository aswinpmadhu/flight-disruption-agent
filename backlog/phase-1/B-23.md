# [domain] SearchPlanner and SearchGuard: cancellation (B-23)

**Phase: P1 · Wave 2 · Milestone cell: M3 (P1) · Priority P0 · Unassigned.**
**Blocked by:** B-03, B-17a. **Blocks:** B-26, B-16a, B-23-P2. **Effort:** 1.0 h (planning estimate; the claimant replaces it). **Class:** SC.
**Prep:** docs/03 §5.5; the interface blocks of B-03 and B-17a.
**Scope (docs/03 §5.5, FR-42), Phase 1:** `SearchPlanner` derives the plan from the **verified booking, the recorded statuses and settings** on every call: origin of the cancelled segment, the booking's final destination, earliest = that segment's **scheduled departure** (T3 anchor), latest = +24 h (T3), cabin from the booking (T4), limit 3. `SearchGuard` decides in order: verified booking; disruption established; origin and destination equal the plan; `earliest_departure` inside the plan range (narrowing allowed); then the service is called with plan values for cabin, window and limit. **The guard re-derives the plan on every call; `Session.search_plan` is a display copy and is never read.** **No consent is read.** Errors carry the allowed values in `details`. The delay-consent and missed-connection branches are Phase 2 (B-23-P2).
**Interface (fixed here):** `SearchPlan(origin, destination, earliest_departure, latest_departure, cabin, limit)`; `SearchPlanner(settings).derive(session) -> SearchPlan | PlanRefusal(error_code, details)`; `SearchGuard(planner).check(session, *, origin, destination, earliest_departure) -> GuardResult(allowed, plan, error_code, details)`.
