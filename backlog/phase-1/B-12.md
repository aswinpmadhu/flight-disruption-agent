# [agent] LLM client interface, ScriptedLLM and AdversarialLLM (B-12)

**Phase: P1 · Wave 1 · Milestone cell: M2 · Priority P0 · Unassigned.**
**Blocked by:** none. **Blocks:** B-25, B-26, B-19, B-32b, B-13, B-31a. **Effort:** 1.5 h (planning estimate; the claimant replaces it). **Class:** -.
**Prep:** none.
**Scope:** `LLMClient` Protocol, one method: system prompt, messages (Anthropic wire-format dictionaries) and tool definitions in, an `LLMResponse` out. **`LLMResponse` (an interface owned by this issue; B-13, B-19, B-25, B-26, B-31a and B-32b build on it):** a frozen model with `stop_reason` (`"end_turn"` or `"tool_use"`), `content` (ordered blocks `{"type":"text","text":...}` and `{"type":"tool_use","id":...,"name":...,"input":{...}}`) and optional `usage`; defined here **without importing `anthropic`**. `ScriptedLLM` replays a fixed list of responses in order. `AdversarialLLM` (docs/03 §9.2) behaves like a compromised model: it may emit any tool call at any moment, including `record_passenger_decision` with `accept_search` or `approve_rebooking`, `search_alternatives`, `execute_rebooking`, **unregistered tool names, extra arguments, and arguments naming a PNR, flight or approval.**
**Files:** `flight_agent/agent/llm_client.py`, `flight_agent/evaluation/scripted_llm.py`, `tests/unit/test_scripted_llm.py`.
**Interface (fixed here):** the method `complete(system, messages, tools) -> LLMResponse`, `LLMResponse`, and the script format; the script path convention is posted in an interface comment within 20 minutes of claiming.
**Acceptance criteria:** scripted responses replay exactly and in order; calling past the end raises a clear error; the adversarial script can emit every call above; an unknown `stop_reason` is rejected; no network; neither file imports `anthropic`, `flight_agent.domain` or `flight_agent.services`.
**Tests you own:** `test_scripted_llm_*`, `test_adversarial_llm_*`. **References:** NFR-08, NFR-09, FR-38; docs/03 §4, §5.1, §8, §9.1, §9.2.
