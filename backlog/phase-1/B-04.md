# [services] Fixture schema, loader and validator (B-04)

**Phase: P1 · Wave 1 · Milestone cell: M2 · Priority P0 · Unassigned.**
**Blocked by:** B-01a. **Blocks:** B-06, B-05, B-05-P2. **Effort:** 1.1 h (planning estimate; the claimant replaces it). **Class:** -.
**Prep:** B-01a text; FR-16; T7.
**Scope:** load JSON fixtures and validate them (S10, FR-16): valid references (bookings to flights), consistent times (arrival after departure; connecting segments in order), unique IDs, synthetic label (FR-36), fictional airline, all times UTC. **DK10 rules:** every `flight_number` matches `^MD[0-9]{3}$`; **`(flight_number, scheduled-departure UTC date)` is unique across all fixture flights.**
**Interface (fixed here):** `load_fixtures(directory) -> FixtureSet(bookings: dict[pnr, Booking], flights: dict[(flight_number, date), FlightRecord], now: datetime, version: str)`; **`FlightRecord`** (an internal record, not a contract model): flight_number, origin, destination, scheduled_departure, scheduled_arrival, status, estimated_departure, estimated_arrival, `seats: dict[cabin, int]`.
**Files:** `flight_agent/services/fixtures.py`, `tests/unit/test_fixtures_validation.py` (tiny inline fixtures).
**Acceptance criteria / tests you own:** `test_fixtures_validation_*`: invalid references, inconsistent times, duplicate IDs, a missing synthetic label are rejected with a message naming the record; **a duplicate `(flight_number, scheduled UTC date)` and a flight number outside the pattern are rejected**; a date taken from an estimated time is not accepted as the date.
**Out of scope:** authoring the data (B-05), MockWorld (B-06), the MCT single-source rule (Phase 2, B-05-P2). **References:** FR-16, FR-36, S10; docs/03 §4, §5.6.
