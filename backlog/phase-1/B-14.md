# [agent] Tool input models, registry, trace recording, hooks (B-14)

**Phase: P1 · Wave 1 · Milestone cell: M2 · Priority P0 · Unassigned.**
**Blocked by:** B-01b, B-18. **Blocks:** B-25, B-26, B-16a, B-16b, B-19, B-37, B-15, B-25-P2. **Effort:** 2.75 h (planning estimate; the claimant replaces it). **Class:** SC.
**Prep:** docs/03 §5.3, §5.4; the B-01b text; B-18's interface.
**Scope:** Pydantic input models for the **eight tools** with the limits of §5.4 (`pnr` 1 to 12 characters, uppercased by the app and **not** pattern-checked so EVAL-04 reaches the lookup; `reported_disruption` one of cancellation, delay, missed_connection, unknown; `date` YYYY-MM-DD; `query` 3 to 200; `origin` and `destination` 3 letters; `earliest_departure` ISO datetime; `option_id`; `decision` one of four; `passenger_words` at most 200). The JSON schema sent to Claude is generated from the same models; every model forbids extra fields; bad arguments return `INVALID_ARGUMENTS`.
**Interface (fixed here):** `Handler = Callable[[BaseModel, Session], Envelope]`. `ToolRegistry`: `register(name, handler)`; `dispatch(session, name, raw_args) -> Envelope`, which validates, calls the handler and **records exactly one trace event per call it receives, allowed or denied**, including an unknown tool name (`INVALID_ARGUMENTS`, the attempted name traced) and invalid arguments; `tool_definitions()`; **`add_end_of_turn_hook(fn, *, when)`** with `when` in `"clean"` or `"always"`; **`run_end_of_turn_hooks(session, *, clean) -> list[str]`**, which runs `always` hooks every time and `clean` hooks only when `clean` is true, in registration order, and returns the non-empty texts. Each handler module exposes `build_handlers(*, <named dependencies>) -> dict[str, Handler]`; the parameters are fixed in the module's own issue; the composition root passes them. There is no shared context type.
**Documented Phase 1 scope exception for FR-07 (decision QD-12, approved by the project owner):** FR-07 and docs/03 §5.4 define eight tools. In Phase 1 the registry registers and advertises **seven** active tools (`get_booking`, `get_flight_status`, `search_policy`, `search_alternatives`, `propose_rebooking_option`, `record_passenger_decision`, `execute_rebooking`); the input model of the eighth tool, `offer_alternative_search`, and the `accept_search` value of `decision` stay as frozen contract with no handler and no Phase 1 behaviour. FR-07 is therefore **partially met, not satisfied**, until B-25-P2 merges; no document, status row or statement may call FR-07 fully satisfied before then.
**Files:** `flight_agent/agent/tools.py`, `flight_agent/agent/registry.py`, `tests/unit/test_tool_registry.py`.
**Acceptance criteria:** unknown fields rejected before any code runs; `execute_rebooking` takes no arguments; the consent-flow and rebooking tools have no PNR, flight, approval or consent parameter (**docs/03 §6.2 L1 says no tool has a parameter for PNR, flight, approval flag or consent flag, yet §5.4 gives `get_booking` a `pnr` and `get_flight_status` a `flight_number`; this issue reads L1 as applying to the authority-bearing tools, namely the consent-flow and rebooking tools, and SP-17 enumerates the exact parameters of every tool so that this reading is tested**); no payment or identity fields. The FR-07 check "tool names in every trace are within the eight" applies to scenario traces; an adversarial test may legitimately trace an unregistered name. **`tool_definitions()` advertises only registered tools. SP-17 asserts the exact parameter lists of all eight models and that the Phase 1 composition advertises seven.** *Permitted tests: SP-17 are boundary or contract-shape tests under the dormant-contract exception defined in the Workflow block; they carry no Phase 2 test ID.*
