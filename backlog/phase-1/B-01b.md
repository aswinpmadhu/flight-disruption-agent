# [domain] Error codes, result envelope and result types (B-01b)

**Phase: P1 · Wave 1 · Milestone cell: M2 · Priority P0 · Unassigned.**
**Blocked by:** B-01a. **Blocks:** B-14, B-01c, B-29a. **Effort:** 1.0 h (planning estimate; the claimant replaces it). **Class:** CT.
**Prep:** docs/03 §5.3, §5.4, §5.6; the B-01a text.
**Scope:** the **tool error-code enum**, every code in the "Error codes" column of docs/03 §5.4 (`BOOKING_NOT_FOUND`, `NO_VERIFIED_BOOKING`, `FLIGHT_NOT_IN_BOOKING`, `FLIGHT_NOT_FOUND`, `DISRUPTION_NOT_ESTABLISHED`, `NOT_APPLICABLE`, `POLICY_NOT_CONSULTED`, `ALREADY_CONSENTED`, `NO_DISRUPTION`, `SEARCH_CONSENT_REQUIRED`, `SEARCH_ARGS_NOT_ALLOWED`, `NO_OPTIONS`, `UNKNOWN_OPTION`, `NO_PENDING_REQUEST`, `REQUEST_NOT_YET_PRESENTED`, `DECISION_KIND_MISMATCH`, `WORDS_NOT_IN_PASSENGER_MESSAGE`, `REPLY_NOT_EXPLICIT`, `FLIGHT_MISMATCH`, `APPROVAL_REQUIRED`, `APPROVAL_ALREADY_USED`, `APPROVAL_INVALIDATED`, `APPROVAL_EXPIRED`, `WRONG_FLIGHT`, `SEATS_UNAVAILABLE`) plus `INVALID_ARGUMENTS`. **Not here:** the API codes of §5.7 (B-20). The **result envelope** (§5.3): `{"ok": true, "data": ...}` or `{"ok": false, "error": {"code", "message", "details"}}`, optional `workflow_note`; success or failure, never both. Service result types (§5.6): `NotFound` and `RebookResult` (ok with the updated `Booking`, or one of `APPROVAL_REQUIRED`, `APPROVAL_ALREADY_USED`, `APPROVAL_INVALIDATED`, `APPROVAL_EXPIRED`, `WRONG_FLIGHT`, `SEATS_UNAVAILABLE`; the service has no pending request, so `NO_PENDING_REQUEST` stays a handler code), appended to `models.py`.
**Files:** `flight_agent/domain/errors.py`, `flight_agent/domain/models.py` (append only), `tests/unit/test_contract_envelope.py`.
**Interface (fixed here):** this text, frozen.
**Tests you own:** `test_contract_envelope_*`: an envelope with both or neither of `data` and `error` is rejected; every §5.4 code exists and none is missing; results frozen and forbid unknown fields; B-01a models unchanged. *Permitted tests: the code-presence assertions for codes that have no Phase 1 behaviour are boundary or contract-shape tests under the dormant-contract exception defined in the Workflow block; they carry no Phase 2 test ID.*
**References:** FR-07, FR-08, FR-24, FR-34; docs/03 §5.3, §5.4, §5.6.
