# [approval] Search consent: filter kind rules, consent record and manager (B-22-P2)

**Phase: P2 · Wave 5 · Milestone cell: M3 (P2) · Priority P0 · Unassigned.**
**Blocked by:** B-22, B-21. **Blocks:** B-25-P2, B-23-P2, B-29b, B-32a-P2. **Effort:** 1.25 h (planning estimate; the claimant replaces it). **Class:** SC.
*Scope:* (1) in `reply_filter.py` (extension after B-21) implement `kind = accept_search`: booking intent without search intent is refused (`BOOKING_INTENT_ONLY`), replacing the Phase 1 `NotImplementedError`. (2) `SearchConsent` record (GRANTED; PNR and disrupted flight **copied from application state**; version; granted turn) and its states NOT_OFFERED, OFFERED, PRESENTED, GRANTED, DECLINED, INVALIDATED (§6.3a). (3) `ConsentManager.decide` for `accept_search`: L2 (a pending `SEARCH_OFFER` exists, presented earlier, latest message) and L3 (exact verbatim words, then the filter) create a GRANTED consent, **clear the SEARCH_OFFER and keep the consent**, and **never create an approval**; refusals leave state unchanged with `details.reason`; `decline` sets DECLINED; `approve_rebooking` with a SEARCH_OFFER pending is `DECISION_KIND_MISMATCH`; a stale offer is `NO_PENDING_REQUEST`; a new PNR or a changed disrupted flight invalidates the consent. (4) consent trace events (B-18 payload). **Only the manager constructs a GRANTED consent.**
*Files:* `reply_filter.py`, `store.py`, `manager.py` (extensions), `tests/unit/test_reply_filter_search.py`, `test_consent_manager_search.py`.
*Acceptance:* accepting a search never creates an approval; a stale offer cannot be reused; all Phase 1 safety tests pass unchanged. *Tests you own:* RF-01-F to RF-06-F, RF-09-F, RF-10-F, RF-11-F (search subset), F-BI; RF-01-S to RF-06-S, RF-09-S, RF-10-S, RF-11-S (search subset); AT-09-C, AT-10-C, AT-11, AT-12, AT-13, AT-14, AT-26, AT-27, AT-28, AT-30; S-1 extension. *Not yours:* AT-15, AT-17, AT-29 (B-25-P2); AT-16, AT-18, AT-31 (B-23-P2). *References:* FR-23, FR-40, FR-41, AC-10, NFR-08; docs/03 §6.
